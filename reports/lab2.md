## 问答题
1. 请列举 SV39 页表页表项的组成，描述其中的标志位有何作用？ 
- RV39的页表项有高到低分别是10bits保留; 44bits物理页号; 2bits软件保留; 8个bits的标志位. 
- 标志位:V: 页表项是否合法; R/W/X分别表示是否允许读写执行; U代表U特权级是否可以访问; A代表是否被访问过; D代表是否被修改. 

2. 缺页
- 请问哪些异常可能是缺页导致的？
    - 访问非法地址
    - 违反标志位
    - 物理页用尽
- 发生缺页时，描述相关重要寄存器的值
    - sstatus保存了trap发生前用户态任务执行的状态(SPP), 此时的全局中断使能(SIE), trap之前的中断使能(SPIE). 从trap恢复时SIE会被恢复成SPIE; sepc记录了导致trap发生的指令的地址或者导致trap发生的指令的下一条指令的地址, 是sret返回的地址. sscrach记录了对应内核态的栈顶指针, 在下次trap时可以用来恢复内核态的上下文. 
- 这样做有哪些好处？
    - 节约内存，避免分配大量未被使用的内存
- 处理 10G 连续的内存页面，对应的 SV39 页表大致占用多少内存 (估算数量级即可)？
    - (10G / 4K / 512 + 10G / 4K / 512 / 512 + 10G / 4K / 512 / 512 / 512) * 4K = 20M
- 请简单思考如何才能实现 Lazy 策略，缺页时又如何处理？
    - 分配MapArea但是不map，在MapArea中增加在可持久化设备位置信息，当缺页发生时查询MapArea如果存在，就完成framed map并从可持久化设备中加载数据。
- 此时页面失效如何表现在页表项(PTE)上？
    - 清除V和U标志位
3. 双页表与单页表
- 在单页表情况下，如何更换页表？
    - 内核态的地址映射设置为相同的，在切换任务时通过内核态的连续性完成页表的切换
- 单页表情况下，如何控制用户态无法访问内核页面？
    - 内核页面对应的页表项的标志位清除U
- 单页表有何优势？
    - 减少了页表切换的次数
- 双页表实现下，何时需要更换页表？假设你写一个单页表操作系统，你会选择何时更换页表（回答合理即可）？
    - 双页表实现下每次trap和restore都需要切换页表
    - 单页表只需要在切换任务时更换页表
